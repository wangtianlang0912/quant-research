# 量化交易研究项目计划书（可执行版）

> **版本**：v1.0  
> **更新日期**：2026-04-29  
> **状态**：执行中 · 第一阶段  

---

## 一、项目目标

构建一套**可实际运行的 MVP 量化交易研究与执行框架**，覆盖从策略研究、回测验证到纸盘交易的完整闭环。

首期不追求大而全，聚焦于：
- 把一个趋势策略和一个均值回归策略跑通完整流程
- 建立可复用的研究基础设施（数据管道、回测框架、风控规则）
- 积累足够长的纸盘记录（≥ 3 个月），为实盘做数据支撑

---

## 二、MVP 范围

### 纳入首期（In Scope）

| 模块 | 具体内容 |
|------|---------|
| 数据层 | A 股日线 + 分钟线历史数据接入（Tushare / AKShare）|
| 策略层 | 1–2 个策略：趋势跟随 + 均值回归 |
| 回测 | 基于 Backtrader 或 VectorBT，含手续费、滑点 |
| 风控 | 单笔止损、最大回撤熔断、仓位上限 |
| 纸盘 | 模拟下单，每日记录持仓与绩效 |
| 记录 | 策略研究文档模板、回测报告模板 |

### 明确排除首期（Out of Scope）

- 高频交易（Tick 级别策略、低延迟系统）
- LLM/大模型驱动的全自动交易
- 多券商实盘对接
- K8s 微服务化部署
- 期权、期货、加密货币策略（研究可以，但不进入执行闭环）
- 分布式大规模计算

---

## 三、非目标（Non-Goals）

- 本项目不是生产级高可用交易系统
- 不追求全市场策略覆盖
- 不进行高频或超短线交易
- 不做面向外部用户的产品

## 五、阶段里程碑

### 第一阶段：基础设施搭建（4 周）

| 周次 | 任务 | 交付物 | 负责人 |
|------|------|--------|--------|
| 第 1 周 | 数据管道搭建 | 日线/分钟线历史数据可查询 | 数据工程师 |
| 第 1 周 | 开发环境标准化 | `configs/` 配置模板，`src/` 框架骨架 | 全员 |
| 第 2 周 | 回测框架配置 | 含手续费/滑点的回测基础可运行 | 策略研究员 |
| 第 3 周 | 策略 #1 研究完成 | `research/` 下策略研究报告 + 回测结果 | 策略研究员 |
| 第 4 周 | 风控规则落地 | `docs/risk-rules.md` 规则运行在框架内 | 风控负责人 |

**里程碑验收**：回测框架可跑通至少一个完整策略，含风控检查。

---

### 第二阶段：策略研究与验证（8 周）

| 周次 | 任务 | 交付物 |
|------|------|--------|
| 第 5–6 周 | 策略 #2 研究 + 回测 | 研究报告 + 回测报告 |
| 第 7 周 | 样本外验证（OOS） | OOS 测试报告 |
| 第 8 周 | 压力测试 + 极端行情分析 | 压力测试报告 |
| 第 9–10 周 | 两策略参数稳健性测试 | 参数敏感性分析文档 |
| 第 11–12 周 | 两策略联合回测（组合层） | 组合回测报告 |

**里程碑验收**：两个策略均通过样本外验证，夏普率 > 1.0，最大回撤 < 15%。

---

### 第三阶段：纸盘交易（12 周）

| 时间 | 任务 |
|------|------|
| 第 1–2 周 | 纸盘环境配置，模拟下单流程打通 |
| 第 3–12 周 | 持续纸盘运行，每周记录绩效 |
| 第 12 周末 | 纸盘绩效评审，决策是否进入实盘 |

**里程碑验收**：纸盘运行 ≥ 3 个月，实际绩效与回测预期吻合度 ≥ 70%，最大回撤未触发熔断。

## 八、成功指标

| 指标 | 目标值 |
|------|--------|
| 回测年化收益 | > 15%（vs 基准沪深 300）|
| 回测夏普比率 | > 1.0 |
| 最大回撤 | < 20% |
| OOS 胜率（相对回测） | ≥ 70% 核心指标吻合 |
| 纸盘运行时长 | ≥ 3 个月不中断 |
| 纸盘与回测绩效吻合度 | ≥ 70% |
| 代码测试覆盖率（核心模块） | ≥ 80% |

---

## 九、验收标准（进入实盘的门禁）

进入实盘交易前，以下条件**必须全部满足**：

- [ ] 策略通过 OOS 验证，核心指标吻合度 ≥ 70%
- [ ] 纸盘运行 ≥ 3 个月，无重大异常
- [ ] 最大回撤未突破阈值
- [ ] 风控规则已完整实现并经过压力测试
- [ ] 发布检查清单（`release-checklist.md`）全部通过
- [ ] 紧急停止（Kill Switch）机制已验证可用
- [ ] 项目负责人签字确认

## 十、执行风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 数据质量问题（缺失、错误） | 中 | 高 | 数据质量检查模块，多源交叉验证 |
| 过拟合（回测好但 OOS 差） | 高 | 高 | 强制样本外测试，参数稳健性分析 |
| 纸盘与实盘执行偏差 | 中 | 中 | 记录滑点、冲击成本，纳入回测参数 |
| 市场环境骤变导致策略失效 | 中 | 高 | 定期重新验证，市场环境识别模块 |
| 团队精力不足拖延里程碑 | 中 | 中 | 范围管控，优先完成核心闭环 |
| 依赖库版本冲突 | 低 | 低 | 固定版本，使用虚拟环境 |
