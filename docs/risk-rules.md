## 一、总则

本文件定义量化交易系统的全套风险控制规则，适用于回测评估、纸盘运行和实盘交易三个阶段。所有规则必须在代码中实现并可审计，禁止手动绕过。

**核心原则**：
1. 保本优先于盈利
2. 所有规则必须有明确的数值阈值，不允许模糊表述
3. 触发动作必须自动执行，不依赖人工判断
4. 所有触发事件必须记录日志并发送告警

## 二、交易前风控（Pre-Trade）

每次生成交易信号后，在实际下单前，必须通过以下所有检查。任一检查失败，该笔交易不得执行。

### 2.1 仓位限制检查

| 规则编号 | 规则描述 | 阈值 | 触发动作 |
|---------|---------|------|---------|
| PT-01 | 单只标的仓位上限 | ≤ 总资产 10% | 拒绝下单，记录日志 |
| PT-02 | 同行业标的合计仓位上限 | ≤ 总资产 30% | 拒绝下单，记录日志 |
| PT-03 | 股票类资产总仓位上限 | ≤ 总资产 90% | 拒绝下单，记录日志 |
| PT-04 | 最大同时持仓标的数量 | ≤ 10 只 | 拒绝开新仓，记录日志 |
| PT-05 | 保留现金比例 | ≥ 总资产 10% | 拒绝下单，记录日志 |

### 2.2 流动性检查

| 规则编号 | 规则描述 | 阈值 | 触发动作 |
|---------|---------|------|---------|
| PT-06 | 单笔委托量不超过标的日均成交量 | ≤ 日均成交量 5% | 拆单或拒绝 |
| PT-07 | 禁止交易停牌、ST 或退市风险标的 | 状态标志检查 | 拒绝下单 |
| PT-08 | 禁止交易上市不足 60 个交易日的次新股 | 上市日期检查 | 拒绝下单 |

### 2.3 状态检查

| 规则编号 | 规则描述 | 触发动作 |
|---------|---------|---------|
| PT-09 | 当日累计亏损已触发日损限，禁止开新仓 | 仅允许平仓操作 |
| PT-10 | 最大回撤已触发熔断，系统处于停止状态 | 拒绝全部下单 |
| PT-11 | Kill Switch 已激活 | 拒绝全部下单 |

## 三、交易中风控（In-Trade）

持仓期间实时监控以下指标，触发条件时自动执行对应动作。

### 3.1 单笔持仓止损/止盈

| 规则编号 | 规则描述 | 阈值 | 触发动作 |
|---------|---------|------|---------|
| IT-01 | 单笔持仓止损（硬止损）| 相对建仓价 -5% | 市价平仓，记录日志 + 告警 |
| IT-02 | 单笔持仓跟踪止损 | 相对最高点回落 -8% | 市价平仓，记录日志 |
| IT-03 | 单笔持仓止盈（可选）| 相对建仓价 +20% | 减仓 50%，记录日志 |

> 注：IT-01 为硬止损，IT-02 为软止损，两者同时生效时取先触发者。

### 3.2 组合级实时监控

| 规则编号 | 规则描述 | 阈值 | 触发动作 |
|---------|---------|------|---------|
| IT-04 | 当日净值跌幅（日损限）| 当日 -3% | 当日停止开新仓，发送告警 |
| IT-05 | 组合浮动亏损（盘中回撤）| 相对当日最高点 -5% | 开始逐步减仓，发送告警 |
| IT-06 | 单日最大亏损额 | 绝对金额（按资金量设定）| 停止全部交易，发送紧急告警 |

### 3.3 执行异常监控

| 规则编号 | 规则描述 | 阈值 | 触发动作 |
|---------|---------|------|---------|
| IT-07 | 委托未成交超时 | 委托后 30 分钟未成交 | 撤单，记录日志 |
| IT-08 | 实际成交价与预期价格偏差（滑点超限）| 偏差 > 1% | 记录异常，累计 > 5 次触发告警 |
| IT-09 | 下单 API 连续失败 | 连续失败 3 次 | 停止系统，发送紧急告警 |

## 四、交易后风控（Post-Trade）

每日收盘后，系统自动执行以下检查并生成报告。

### 4.1 绩效归因与偏差检查

| 规则编号 | 规则描述 | 频率 |
|---------|---------|------|
| PO-01 | 与回测/纸盘预期对比，生成偏差报告 | 每日 |
| PO-02 | 换手率计算，超过预期时记录原因 | 每日 |
| PO-03 | 交易成本统计（手续费 + 滑点）| 每日 |

### 4.2 每日收盘检查

| 规则编号 | 检查项 | 异常标准 | 动作 |
|---------|--------|---------|------|
| PO-04 | 持仓与预期持仓对比 | 任何差异 | 记录并告警 |
| PO-05 | 账户净值计算与券商对账 | 差异 > 0.01% | 停止次日交易，人工核查 |
| PO-06 | 风控规则触发日志审查 | — | 每日生成报告 |

### 4.3 周期性检查

| 规则编号 | 检查项 | 频率 | 负责人 |
|---------|--------|------|--------|
| PO-07 | 策略实盘与回测指标对比 | 每周 | 策略研究员 |
| PO-08 | 风控参数是否需要调整 | 每月 | 风控负责人 |
| PO-09 | 完整风险审计 | 每季度 | 项目负责人 |

## 五、暴露度限制（Exposure Limits）

| 维度 | 限制 | 说明 |
|------|------|------|
| 单一标的 | ≤ 10% | 占总资产比例 |
| 单一行业 | ≤ 30% | 申万一级行业 |
| 股票总仓位 | ≤ 90% | 保留 ≥ 10% 现金 |
| 单一策略 | ≤ 50% | 多策略场景下限制单策略集中度 |
| 市值风格 | 大/中/小盘偏离基准 ≤ 30% | 防止风格极度集中 |

## 六、回撤处理规则（Drawdown Actions）

| 回撤级别 | 触发条件 | 强制动作 | 解除条件 |
|---------|---------|---------|---------|
| 一级警告 | 净值回撤 -8% | 停止开新仓，发送警告 | 净值回到 -5% 以内，人工确认 |
| 二级警告 | 净值回撤 -12% | 所有仓位减半，发送紧急告警 | 人工审核后，项目负责人解除 |
| 熔断 | 净值回撤 -20% | 全部平仓，停止系统 | 完整风险审查 + 项目负责人签字后恢复 |

> 回撤以上线初始净值（或上次重置净值）为基准计算。

## 七、Kill Switch（紧急停止）

### 7.1 自动触发 Kill Switch 的条件

- 净值单日下跌 ≥ 5%
- 净值最大回撤 ≥ 20%
- 连续 5 个交易日亏损，且累计亏损 ≥ 8%
- 下单 API 连续失败 ≥ 5 次
- 系统检测到账户资金异常（与预期差异 > 5%）
- 监控系统检测到策略信号生成异常（如连续相同信号）

### 7.2 Kill Switch 执行流程

```
1. 自动触发：停止一切新下单
2. 市价平仓所有持仓（按优先级：流动性差的先平）
3. 发送紧急告警（短信 + 邮件 + 企业微信）
4. 记录触发原因和当时系统状态快照
5. 系统进入锁定状态，仅允许人工干预
6. 人工审查：识别根本原因，制定修复方案
7. 项目负责人签字解除锁定
```

### 7.3 手动触发 Kill Switch

任何团队成员发现异常，均可通过以下方式手动触发：
- 系统管理界面一键停止按钮
- 命令行：`python -m src.kill_switch --reason "描述原因"`
- 直接修改配置：将 `configs/runtime.yaml` 中 `kill_switch: true`

## 八、日志与告警（Logging & Alerts）

### 8.1 必须记录的日志事件

| 事件类型 | 日志级别 | 日志内容 |
|---------|---------|---------|
| 交易信号生成 | INFO | 时间、标的、方向、信号强度 |
| 下单操作 | INFO | 时间、标的、数量、价格、原因 |
| 成交回报 | INFO | 时间、标的、成交量、成交价 |
| 风控规则触发 | WARNING | 规则编号、触发值、执行动作 |
| Kill Switch 触发 | ERROR | 触发原因、系统状态、时间 |
| 系统异常 | ERROR | 异常类型、堆栈、时间 |
| 对账差异 | ERROR | 差异金额、差异原因 |

### 8.2 告警分级与通知方式

| 级别 | 触发场景 | 通知方式 | 响应时限 |
|------|---------|---------|---------|
| P1 紧急 | Kill Switch、API 故障、账户异常 | 短信 + 电话 | 15 分钟内响应 |
| P2 重要 | 止损触发、回撤警告 | 企业微信 + 邮件 | 1 小时内响应 |
| P3 关注 | 日损限触发、参数偏离 | 企业微信 | 当日响应 |
| P4 信息 | 日常报告、绩效汇总 | 邮件 | 次日响应 |

### 8.3 日志保存要求

- 所有交易日志保存 ≥ 3 年
- 日志文件不可被程序自动删除
- 每日日志备份到独立存储
- 日志格式：结构化 JSON，含时间戳（精确到毫秒）

## 九、紧急响应流程（Emergency Response）

### 9.1 系统崩溃响应

```
1. Kill Switch 自动触发（如系统未崩溃）
2. 人工立即登录券商 APP，确认持仓状态
3. 如有未平持仓，人工在券商 APP 平仓
4. 记录崩溃时间点和系统状态
5. 排查根本原因（代码 Bug / 数据异常 / 网络故障）
6. 修复并通过测试后，走完整发布流程再恢复运行
```

### 9.2 数据异常响应

```
1. 系统检测到数据异常 → 自动停止信号生成
2. 切换到备用数据源（如有）
3. 人工核查异常数据内容和影响范围
4. 确认数据清洗/修复完成后恢复
5. 记录异常数据影响的时间范围，后续回测需标注
```

### 9.3 市场极端行情响应

```
1. 监控系统检测到标的或市场指数单日波动 > 7%
2. 发送 P2 告警，人工评估策略是否继续运行
3. 可选：临时提高止损阈值或暂停策略
4. 事后分析极端行情对策略的影响
5. 更新压力测试场景并重新评估策略
```

## 十一、免责与边界

- 本文件规则仅适用于本项目管辖的策略和账户
- 规则本身不能消除所有损失风险，仅为风险控制框架
- 市场极端情况可能导致规则失效（如涨跌停板封单无法平仓）
- 首期为纸盘/模拟交易，实盘前须完整复核本文件所有规则
