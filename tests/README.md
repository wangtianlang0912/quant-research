# tests/ — 测试目录

本目录包含项目所有单元测试和集成测试。

---

## 测试策略

| 测试类型 | 目录 | 说明 |
|---------|------|------|
| 单元测试 | `tests/unit/` | 测试单个函数/类，不依赖外部服务 |
| 集成测试 | `tests/integration/` | 测试模块间协作，可能需要测试数据库或模拟数据源 |
| 风控测试 | `tests/risk/` | 专门测试风控规则触发是否正确 |

---

## 测试覆盖率目标

| 模块 | 目标覆盖率 |
|------|---------|
| `src/risk/` | ≥ 90%（风控为核心安全防线）|
| `src/data/` | ≥ 80% |
| `src/strategy/` | ≥ 80% |
| `src/execution/` | ≥ 80% |
| `src/utils/` | ≥ 70% |

---

## 运行测试

```bash
# 运行所有测试
pytest tests/

# 运行特定模块测试
pytest tests/unit/test_risk.py

# 运行并查看覆盖率报告
pytest tests/ --cov=src --cov-report=html
```

---

## 测试规范

- 每个测试函数名以 `test_` 开头，描述清晰（如 `test_stop_loss_triggers_on_5pct_drop`）
- 使用 Mock/Stub 隔离外部依赖（API、数据库）
- 风控规则的每个条件必须有对应的正向测试和边界测试
- 禁止测试依赖真实网络请求（使用 `pytest-mock` 或 `responses` 库）
- CI 环境中所有测试必须通过才能合并 PR

---

## 优先测试场景

以下场景必须有测试覆盖：

1. **风控规则**：每条规则的触发条件和非触发条件
2. **Kill Switch**：自动触发和手动触发
3. **数据异常处理**：缺失值、极端值、空数据集
4. **信号边界条件**：参数边界、无信号情况
5. **仓位计算**：各种资金量和权重组合
